# Synthetic fixture corpus

57 fake personal documents in 18 languages and 8 scripts, plus five negative cases. The extractor tests
read them to check text layers, OCR, encodings and entities. The evaluation (`arrumatorcli eval Tests/Fixtures`) uses
them to measure how well documents are read against `expected.json`.

Everything here is generated by `Tools/FixtureGen` from a seed. **Do not edit these files by hand.** Change the
generator and render the corpus again.

```bash
# render (replaces pt/ ru/ en/ intl/ negative/ and expected.json; this README is left alone)
swift run --package-path Tools/FixtureGen fixturegen --out Tests/Fixtures --seed 42

# check files, text layers, identifiers, Vision OCR legibility and byte-for-byte reproducibility
swift run --package-path Tools/FixtureGen fixturegen --verify Tests/Fixtures
```

`--verify` exits non-zero on any failure. It takes about 20 seconds because it OCRs every scan and photo and
renders the whole corpus again into a temporary directory. The line "CoreGraphics PDF has logged an error" is
expected: it comes from PDFKit probing the deliberately truncated PDF.

## Layout

```text
expected.json     ground truth, one entry per file (schema below)
pt/  01–16        Maria Exemplo's household in Lisbon
ru/  20–31        Иван Тестов in Moscow
en/  40–47        Alex Sample, a UK national living in Lisbon
intl/ 50–70       one household each in Germany, France, Spain, Mexico, Italy, the Netherlands, Poland, Sweden, Czechia,
                  Ukraine, Turkey, Greece, China, Japan, Korea, the UAE, India, California and Brazil
negative/ 90–94   edge cases: a self-made spreadsheet, a copy, a blank scan, an encrypted and a damaged PDF
```

## `expected.json`

```json
{ "schema": 1, "baseline_version": 1, "seed": 42, "fixtures": [
  { "file": "pt/04-at-irs-modelo3-2025.pdf", "lang": "pt", "kind": "pdf-text",
    "expected": { "status": "filed", "doc_type": "tax-return", "correspondent": "Autoridade Tributária",
                  "date": "2026-05-20", "title_contains": ["Modelo 3", "2025"], "identifiers": ["ptNIF:999999990"] } },
  { "file": "pt/13-continente-talao.jpeg", "lang": "pt", "kind": "image-photo",
    "expected": { "status": "filed", "doc_type": "receipt", "correspondent": "Continente", "date": "2026-09-14",
                  "title_contains": ["Fatura", "simplificada"], "identifiers": ["ptNIF:999999990", "ptNIF:595605966"] },
    "accept_also": { "doc_type": ["invoice"] } } ] }
```

| Field | Meaning |
|---|---|
| `lang` | The document's main language as its ISO 639-1 code (`pt`, `ru`, `en`, `de`, `ja`, …), or `und` (no readable text) |
| `kind` | `pdf-text`, `pdf-scan`, `image-photo`, `image-screenshot`, `docx`, `xlsx`, `text`, `eml` (the generator has no `pptx` fixture yet) |
| `expected.status` | `filed` for an ordinary document; `needsReview` for one the app cannot read (blank, encrypted, damaged); `duplicate` for the byte-identical copy, which reads its original again |
| `expected.doc_type` | The expected `type` label, from the app's `DocumentType` vocabulary; `null` when the file is not read (duplicate, unreadable) |
| `expected.correspondent` | The expected `sender` label: the name as the document writes it, in its own script; `accept_also` lists other forms, such as a transliteration |
| `expected.date` | The expected `date` label: the issue date (never a due, period or birth date) as `YYYY-MM-DD` |
| `expected.title_contains` | Words the generated file name should contain, matched ignoring case and accents. All of them also appear in the document itself |
| `expected.identifiers` | Every checksum-valid stable key in the document, as `kind:value` tokens (`ptNIF:…`, `ruINN:…`, `iban:…` without spaces). The list is complete: the generator and `--verify` fail if the text contains a 9-digit mod-11-valid number or a 10/12-digit checksum-valid ИНН that is not listed |
| `expected.warnings` | Extraction warnings the app should raise (`encrypted`, `corrupted`, `encodingGuessed`, `emptyText`); present only when non-empty |
| `expected.labels` | Other labels the document should get, by kind (`party`, `object`, `reference`, `period`, `deadline`, `amount`, `jurisdiction`): each value, or one of its alternatives separated by a vertical bar, must be found in a label of that kind. Amounts are `number CODE`; dates and periods as the app writes them. Present only on the international documents |
| `accept_also` | Alternative answers that still count as a pass, per field (`doc_type`, `correspondent`) |
| `duplicate_of` | Only on the duplicate: the file it is byte-identical to |
| `encoding` | Only on `text` fixtures: `koi8-r` or `utf-8` |
| `password` | Only on the encrypted PDF: its user password (the app is not given it) |
| `invalid_identifiers` | Look-alike numbers in the text that fail their checksum; an extractor must not report them |
| `seed` | Seed the corpus was rendered with; `--verify` re-renders with it |

## What `--verify` checks

- Every file in `expected.json` exists and is not empty.
- Text-layer formats (text PDFs, DOCX, XLSX, text, EML) contain every `title_contains` word and every identifier.
  They contain no unlisted checksum-valid NIF or ИНН, and every `invalid_identifiers` distractor is present.
- Scanned PDFs have no text layer. Scanned pages and images are OCRed with Vision (`RecognizeTextRequest`,
  `.accurate`, the fixture's own language first, then en/ru/pt). At least 60 % of `title_contains` must
  be recovered. At present every OCR fixture recovers 100 %, and every printed identifier is recovered too.
- Photos carry EXIF `DateTimeOriginal`. The blank scan OCRs to nothing. The KOI8-R file is not valid UTF-8. The
  EML has the expected MIME structure.
- The encrypted PDF is locked, an empty password fails, and the recorded password opens it. PDFKit cannot read
  the truncated PDF. The duplicate is byte-identical to its original.
- The corpus is rendered again into a temporary directory. Every file, `expected.json` included, must be
  byte-identical, except `negative/93-encrypted.pdf`: PDF encryption salts every run.

## How the files are made

| Kind | Technique |
|---|---|
| pdf-text | CoreText lays out the document into an A4 `CGPDFContext`, so the file has a real text layer with embedded font subsets (Helvetica Neue, Times New Roman). Quartz writes the wall-clock time into CreationDate/ModDate and a time-derived `/ID`. The generator overwrites these in place with same-length values: the document date and a hash of the file name. |
| pdf-scan | The page is rendered at 12 pt and rasterised at 150 dpi in grey. It is then skewed by a seeded 0.6–1.2°, blurred slightly, and given lower contrast, seeded pixel noise, dust specks and a lid shadow. The result is JPEG-encoded and embedded as the only content of the page, with no text layer. |
| image-photo | A receipt printed in monospace on torn thermal paper, or a card drawn in millimetres with guilloche print, placed on a table with `CIPerspectiveTransform` keystone, drop shadow, `CIVignette`, blur and sensor noise. Written as JPEG or HEIC by `CGImageDestination` with EXIF `DateTimeOriginal` and `OffsetTimeOriginal`. |
| image-screenshot | CoreGraphics draws a banking-app details screen at 1179 × 2556 px (PNG). |
| docx | `NSAttributedString.data(from:documentAttributes:)` with `.officeOpenXML`, then zipped again with fixed entry timestamps. |
| xlsx | SpreadsheetML parts written by hand (inline strings, styles, formulas with cached values), zipped by `/usr/bin/zip -X -r` in UTC with fixed timestamps. |
| eml | RFC 5322/MIME with CRLF line endings. |
| text | KOI8-R or UTF-8, no BOM. |

Core Image runs on the CPU renderer. All randomness comes from SplitMix64 streams seeded by the corpus seed and
the file name, so adding a fixture does not change the others. Every tunable value (DPI, rotation range, noise,
blur, JPEG/HEIC quality, spacing) lives in `RenderSettings.standard`.

Byte-for-byte identity is guaranteed on the same macOS build. PDFs record the Quartz producer string, which
contains the OS version, and system image codecs can change between releases. After a macOS update, render the
corpus again and commit it if `--verify` reports differences.

## Fake-data policy

- **No real person appears anywhere.** The people are Maria Exemplo, João Exemplo, Иван Тестов, Пётр Образцов
  and Alex Sample, the households of the international set (Anna Beispiel, Julien Exemple, 山田 花子 and others,
  named with each language's word for "example" or "sample" where it has one), plus staff names such as
  "Dra. Ana Exemplo". Addresses are "Rua Exemplo …", "ул. Тестовая …",
  "Beispielstraße …" and similar, and so are the organisations' own addresses in the international set. Phone
  numbers are placeholders (210 000 000, +7 495 000-00-00, 0800 000 000). E-mail
  recipients use `example.com`.
- **Identifiers are fictitious but checksum-valid**, so extractors see realistic keys:
  - NIF `999999990`, the canonical test value.
  - IBAN `PT50 0002 0123 1234 5678 9015 4`, the public sample.
  - All other NIF/NIPC, NISS, ИНН (10 and 12 digits), СНИЛС, IBANs with national check digits, and Russian
    accounts with БИК control keys are generated with the real algorithms.
  - Reference numbers of 9, 10 or 12 digits are drawn so that they never pass a NIF or ИНН check.
  - The invalid NIF test value is `123456780`. The often-quoted `123456789` actually passes mod-11.
  - The passport number, MRZ and SPECIMEN overprint are fabricated.
- **Organisations appear under their real brand names** (EDP, MEO, Autoridade Tributária, AIMA, Сбербанк, ФНС,
  Ингосстрах, Hetzner, JetBrains, Revolut, TAP, and in the international set SWM, MAPFRE, CFE, Orange, Turkcell,
  TEPCO, Enel…), because reading the sender is part of what is
  tested. Public identifiers such as a bank's BIC or a website may appear. Every tax number, account, address and
  amount attributed to them is invented. The AIMA e-mail uses the sender domain `aima.gov.pt`.
- Every PDF says it is synthetic in its Creator entry ("Arrumator FixtureGen (synthetic test document)"). Every
  photo says so in the TIFF Software tag.
- Real documents never belong here. Use `Tests/Fixtures/private/`, which is ignored by git.

## Adding a fixture

1. Add a builder to `Tools/FixtureGen/Sources/FixtureGen/Content/{PT,RU,EN,International,Negative}.swift`. Use
   `Fixture.filed(…)` for an ordinary document, or `Fixture.edgeCase(…)` for one that is not, with the status the app
   should give it,
   and list it in that file's `all(cast:seed:)`.
2. Create any randomness with `Fake(seed: seed, salt: file)`. Take shared people and organisations from `Cast`.
   Use `fake.reference(n)` for numbers that must not look like identifiers.
3. Render the corpus, run `--verify`, look at the file, and commit the generator change together with the
   regenerated fixtures.
